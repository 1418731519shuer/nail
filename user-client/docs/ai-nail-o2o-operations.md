# AI 美甲试戴驱动型 O2O 款式运营系统

## 1. 产品定位

本产品不能简单理解为仿淘宝、京东或拼多多的美甲电商。更准确的定位是：

```text
内容种草平台 + AI 虚拟试戴工具 + 本地到店服务电商
```

电商漏斗可以借鉴，但不能照搬。传统电商关注“商品曝光、加购、下单、支付、履约”，而美甲服务还存在试戴效果、门店能力、材料准备、美甲师档期、线下沟通、到店后换款等环节。

因此，本系统的核心链路应重构为：

```text
外部趋势采集
→ 款式知识库
→ 用户端款式曝光
→ 加入试戴候选
→ 生成 AI 试戴
→ 查看试戴结果
→ 我想做
→ 到店确认做
```

最终目标不是单纯做款式展示，而是建立一个能把外部流行趋势、本店真实偏好、AI 试戴反馈和线下成交结果连接起来的闭环系统。

## 2. 核心口径

| 概念 | 推荐定义 | 不建议定义 | 说明 |
|---|---|---|---|
| 试戴列表 | 款式候选池 / 试戴候选 | 购物车 | 用户只是想看上手效果，不代表准备购买。 |
| 加入试戴 | 候选加入行为 | 加购 | 强于浏览，弱于下单。 |
| 收藏 | 长期兴趣信号 | 主漏斗必经节点 | 收藏代表以后看，不代表当下强意向。 |
| 我想做 | 候选意向池 / 服务型购物车 | 成交 | 用户把款式放入候选池，适合稍后比较，不再是确认做的唯一前置条件。 |
| 确认做/下单 | 强意向动作 / 预约成交 | 普通点击行为 | 可由卡片、详情、试戴结果、我想做列表多入口触发；MVP 阶段可默认等同成交。 |
| 爆款 | 分层爆款 | 销量 Top10% | 早期成交不足，应分趋势、试戴、意向、成交四层。 |
| 冷门 | 漏斗断点诊断结果 | 低热度款 | 低热度可能只是曝光不足，不能直接判断冷门。 |

必须统一三条口径：

```text
试戴 = 深度兴趣 / 体验型收藏
我想做 = 加入购物车 / 强意向加购
确认做/下单 = 预约成交
```

MVP 阶段可以先把“确认做/下单”默认作为成交口径。后续如果要更真实，再拆成：

```text
预约成交 = 确认做/下单
实际成交 = 到店完成服务
```

## 3. 用户链路

主链路：

```text
首页/搜索/分类曝光
→ 点击款式卡片
→ 加入试戴候选池
→ 上传或选择手部图
→ 生成 AI 试戴结果
→ 查看试戴效果
→ 点击“我想做”
→ 预约/联系门店
→ 到店确认做
```

并行行为：

```text
浏览款式
├─ 收藏：长期兴趣
├─ 加入试戴候选：体验意愿
├─ 查看详情：降低决策风险
└─ 我想做：强消费意向
```

收藏不能作为主漏斗必经节点。用户可以不收藏，直接试戴并表达“我想做”。

## 4. 现在需要新增的功能

### 4.1 外部趋势采集

目的：回答“外部平台最近什么款式热”，用于发现候选款和辅助上新。

需要支持：

- 采集小红书等平台的关键词趋势，如新中式、猫眼、通勤短甲、法式、裸色。
- 记录笔记互动数据：点赞、收藏、评论、发布时间、近期增长。
- 保存趋势图片，并区分参考图、可商用图、门店实拍图。
- 自动归纳趋势标签：颜色、风格、甲型、季节、场景、元素。
- 计算 `XHS_TrendScore` 外部趋势分。

注意：外部趋势分不能直接决定本店首页推荐，只能用于上新和趋势发现。

### 4.2 款式知识库

目的：把“图片”变成可搜索、可推荐、可试戴、可服务的结构化款式。

基础字段：

```text
style_id
style_name
style_images
style_category
color_tags
scene_tags
nail_shape_tags
style_elements
source_type
source_url
copyright_status
created_at
status
```

### 4.3 门店可服务性

目的：判断款式能不能在本店真实履约。

建议字段：

```text
store_can_make
required_materials
missing_materials
material_cost_level
difficulty_level
estimated_duration
nail_artist_level
suitable_nail_length
suitable_nail_shape
suitable_skin_tone
maintenance_risk
price_range
service_note
```

这个模块用于避免“小红书很火，但本店做不了或做不好”的问题。

### 4.4 用户端款式浏览

需要支持：

- 首页推荐流：本店热款、趋势款、新款、适合短甲、通勤款。
- 分类筛选：风格、颜色、甲型、价格、时长、难度。
- 款式卡片操作：收藏、加入试戴候选、查看详情、直接试戴。
- 卡片服务提示：本店可做、预计时长、参考价格、适合甲型。

### 4.5 试戴候选池

定位：候选池，不是购物车。

需要支持：

- 加入候选款。
- 删除候选款。
- 批量生成试戴。
- 多款横向对比。
- 标记最喜欢款式。
- 从候选池进入“我想做”。

### 4.6 AI 试戴生成

需要支持：

- 手部图片上传或复用历史手图。
- 单款试戴生成。
- 多款批量试戴生成。
- 生成进度、失败提示、重试。
- 结果保存、分享、重新生成。
- 试戴前后对比。

### 4.7 试戴结果页

定位：体验确认和强意向转化节点。

需要展示：

- 试戴效果图。
- 原款式图。
- 适合甲型、适合肤色、预计时长。
- 参考价格。
- 门店是否可做。
- 维护风险说明。
- 操作按钮：收藏结果、换一款、重新生成、我想做。

### 4.8 款式详情页

定位：不是主路径，但负责降低决策风险。

需要展示：

- 款式介绍。
- 价格区间。
- 制作时长。
- 所需材料。
- 是否需要延长甲。
- 是否容易掉钻或磨损。
- 适合甲型和肤色。
- 门店可做情况。
- 美甲师建议。

### 4.9 “我想做”意向

定位：强消费意向，不是成交。

需要支持：

- 从试戴结果页提交“我想做”。
- 从详情页提交“我想做”。
- 选择门店或默认门店。
- 留下时间偏好、价格接受区间、备注。
- 允许取消或修改意向。

### 4.10 门店确认

目的：把线上强意向转成线下成交结果。

需要支持：

- 查看用户想做款式和试戴图。
- 判断是否可做。
- 确认预约时间。
- 标记到店确认做。
- 标记到店换款。
- 标记无法履约原因：材料不足、价格不接受、档期不合适、用户改款。
- 记录最终成交款式、实际价格、实际耗时。

### 4.11 爆款分层

系统应支持四类爆款：

```text
趋势爆款：外部平台热度高、近期增长快
试戴爆款：加入试戴和生成试戴高
意向爆款：试戴后“我想做”高
成交爆款：到店确认做高、换款率低
```

### 4.12 冷门预警

冷门判断必须先看样本量，再看断点。

| 类型 | 判断条件 | 运营含义 |
|---|---|---|
| 未充分测试 | 曝光不足 | 不能判断冷门，需要增加曝光。 |
| 第一眼不吸引 | 曝光高、加入试戴低 | 封面图、标题或款式第一眼不够吸引。 |
| 体验转化弱 | 加入试戴高、生成试戴低 | 试戴流程可能太复杂，或用户犹豫。 |
| 上手效果差 | 试戴查看高、我想做低 | 款式试戴后劝退。 |
| 门店转化差 | 我想做高、到店确认低 | 价格、档期、门店履约能力存在问题。 |
| 到店换款高 | 到店后经常换款 | 线上试戴效果和线下预期不一致。 |

### 4.13 多款比较归因

用户可能一次试戴 5 个款式，只选择 1 个“我想做”。未被选中的 4 个不能简单记为失败。

需要记录：

- 用户一次试戴了哪些款。
- 哪些款进入对比。
- 哪一款最终被选择为“我想做”。
- 其他款式是被淘汰、收藏，还是后续再看。

核心指标：

```text
多款比较胜出率 = 某款在多款试戴场景下被选为“我想做”的次数 / 该款参与多款比较的次数
```

## 5. 需要计量的指标

### 5.1 主漏斗指标

| 指标 | 公式 | 含义 |
|---|---|---|
| 曝光点击率 | 款式点击人数 / 款式曝光人数 | 款式第一眼吸引力。 |
| 候选加入率 | 加入试戴候选人数 / 款式曝光人数 | 用户是否愿意把款式放入候选池。 |
| 详情查看率 | 详情页查看人数 / 款式点击人数 | 用户是否需要进一步了解信息。 |
| 试戴生成率 | 成功生成试戴人数 / 加入试戴候选人数 | 候选款是否真正进入体验环节。 |
| 试戴结果查看率 | 查看试戴结果人数 / 成功生成试戴人数 | 用户是否完成体验闭环。 |
| 试戴结果意向率 | 点击“我想做”人数 / 查看试戴结果人数 | 试戴结果是否促成强意向。 |
| 到店确认率 | 到店确认做人数 / 点击“我想做”人数 | 强意向到线下成交的转化能力。 |
| 试戴成交率 | 到店确认做人数 / 查看试戴结果人数 | AI 试戴结果最终带来的成交效率。 |

### 5.2 款式运营指标

| 指标 | 含义 |
|---|---|
| 款式曝光量 | 判断样本量是否足够。 |
| 款式点击量 | 判断封面、标题、标签吸引力。 |
| 加入试戴次数 | 判断候选热度。 |
| 试戴生成次数 | 判断实际体验热度。 |
| 试戴结果保存次数 | 判断用户是否愿意保留结果。 |
| “我想做”次数 | 判断强意向热度。 |
| 到店确认次数 | 判断真实成交热度。 |
| 到店换款率 | 判断线上效果与线下预期是否一致。 |
| 门店拒单率 | 判断款式是否超出门店服务能力。 |
| 平均制作时长 | 判断履约成本。 |
| 平均实际价格 | 判断商业价值。 |

### 5.3 多款比较指标

| 指标 | 公式 | 含义 |
|---|---|---|
| 参与比较次数 | 某款进入多款试戴组合的次数 | 款式被拿来比较的频率。 |
| 比较胜出次数 | 某款在组合中被选为“我想做”的次数 | 款式竞争力。 |
| 多款比较胜出率 | 比较胜出次数 / 参与比较次数 | 比单纯试戴次数更可靠。 |
| 比较落败后收藏率 | 落败后收藏次数 / 落败次数 | 款式是否仍有长期兴趣。 |

### 5.4 服务履约指标

| 指标 | 含义 |
|---|---|
| 门店可做率 | 入库款式中门店可做的比例。 |
| 材料齐全率 | 款式所需材料是否可满足。 |
| 美甲师匹配率 | 是否有合适等级美甲师可做。 |
| 预约成功率 | “我想做”后成功预约比例。 |
| 到店确认率 | 预约或意向最终到店确认比例。 |
| 到店换款率 | 用户到店后改做其他款式比例。 |
| 实际价格偏差 | 实际价格与展示价格区间的偏差。 |
| 实际时长偏差 | 实际制作时长与预计时长的偏差。 |

### 5.5 偏好指标

| 指标 | 计算逻辑 | 用途 |
|---|---|---|
| 热门颜色偏好 | 按试戴、我想做、到店确认聚合颜色标签 | 指导选品和推荐。 |
| 热门风格偏好 | 按试戴、我想做、到店确认聚合风格标签 | 判断通勤、甜酷、法式、猫眼等偏好。 |
| 热门甲型偏好 | 按试戴、我想做、到店确认聚合甲型标签 | 判断短甲、方圆、杏仁、长甲偏好。 |
| 用户偏好画像 | 用户行为加权生成 | 个性化推荐。 |
| 门店偏好画像 | 门店所有用户偏好聚合 | 指导门店上新。 |

## 6. 分数体系

### 6.1 XHS_TrendScore

外部趋势分，用于发现候选款和辅助上新。

可由以下因素构成：

```text
点赞量
收藏量
评论量
发布时间新鲜度
近期增长速度
同类笔记密度
关键词热度
```

### 6.2 LocalHotScore

本店热款分，用于首页推荐、本店热款榜、运营复盘。

可由以下因素构成：

```text
曝光点击率
候选加入率
试戴生成率
试戴结果意向率
到店确认率
到店换款率反向指标
```

### 6.3 StyleQualityScore

款式质量分，用于入库审核和低质量过滤。

可由以下因素构成：

```text
图片质量
试戴适配度
标签完整度
版权状态
门店审核状态
是否可生成稳定试戴结果
```

### 6.4 ServiceabilityScore

可服务性分，用于门店上架、预约前提示、履约风险控制。

可由以下因素构成：

```text
门店是否可做
材料是否齐全
制作难度
预计时长
美甲师等级要求
维护风险
价格是否适合本店客群
```

### 6.5 推荐分使用规则

不建议把外部热度、本店热度、款式质量和可服务性混成一个不可解释的总分。

建议按场景使用：

```text
上新参考：XHS_TrendScore + StyleQualityScore
首页推荐：LocalHotScore + ServiceabilityScore
爆款判断：趋势、试戴、意向、成交分层判断
门店运营：到店确认率、换款率、履约成本
```

## 9. MVP 优先级

### P0：必须先做

- 款式知识库基础字段。
- 首页/分类/搜索曝光。
- 加入试戴候选池。
- AI 试戴生成与结果查看。
- “我想做”意向提交。
- 门店确认做。

- 基础数据看板。

### P3：长期优化

- 个性化推荐。

- 价格预测。
- 预约档期自动匹配。
- 多门店差异化推荐。

## 10. 最终结论

本系统的合理表达不是“模仿电商”，而是：

```text
借鉴电商漏斗，但重构为 AI 美甲试戴的服务型转化链路。
```

核心闭环是：
