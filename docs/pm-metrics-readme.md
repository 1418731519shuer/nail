# AI 美甲试戴产品指标 README（PM 版）

## 1. 产品定位

本产品不是单纯电商，也不是单纯 AI 生图工具，而是：

```text
内容种草平台 + AI 美甲试戴工具 + 本地到店服务预约成交
```

因此指标不能只照搬“浏览 -> 加购 -> 下单”，而要改成“多入口强意向转化”。

## 2. 最新业务口径

```text
浏览 = 用户看到款式
试戴 = 用户对款式产生体验兴趣
我想做 = 候选意向池，类似购物车/愿望单混合
确认要做 = 强意向动作，MVP 阶段默认等同预约成交
确认做/下单 = 预约成交
```

关键变化：

```text
“我想做”不是“确认要做”的唯一前置条件。
```

用户可以从多个位置直接确认要做：

```text
路径 A：浏览款式 -> 直接确认要做
路径 B：浏览款式 -> 我想做 -> 确认要做
路径 C：浏览款式 -> 试戴 -> 试戴结果页确认要做
路径 D：浏览款式 -> 试戴 -> 试戴结果页我想做 -> 确认要做
路径 E：详情页 -> 确认要做
```

## 3. 为什么这样定义

外部参考给出的判断：

- Shopify 的 Buy Button / Buy It Now 思路说明，购买动作可以放在内容页、商品页或外部页面中，不必强制先进入购物车。
- Shopify 动态结账按钮说明，Buy it now 可以跳过购物车直接进入结账。
- Baymard 的结账研究显示，结账复杂度会导致流失，减少不必要步骤是提升转化的重要方向。
- AR/虚拟试穿研究普遍认为，AR 会提高商品诊断性、降低感知风险，并影响购买意向。

迁移到本产品：

```text
用户已经被款式或试戴结果打动时，应允许直接确认要做。
```

## 4. 核心北极星指标

| 指标 | 公式 | 作用 | 优先级 |
| --- | --- | --- | --- |
| 预约成交数 | 确认要做/下单次数 | MVP 阶段最接近商业结果 | P0 |
| 总确认率 | 确认要做总人数 / 款式浏览人数 | 判断整体转化能力 | P0 |
| 试戴后确认率 | 试戴结果页确认要做人数 / 试戴结果查看人数 | 判断 AI 试戴是否真正促成决策 | P0 |
| 直接确认率 | 卡片或详情页直接确认要做人数 / 浏览人数 | 判断款式第一眼强成交能力 | P0 |
| 想要转确认率 | 从我想做列表确认人数 / 我想做人数 | 判断候选池沉淀价值 | P0 |

## 5. 多路径转化指标

有效浏览口径：

```text
card_render_pv = 卡片被渲染，只做技术日志
impression_uv = 卡片可见面积 >= 50%，连续 >= 1 秒
view_uv = 卡片可见面积 >= 70%，连续 >= 2 秒
```

转化率分母优先用 `view_uv`，不要用 `card_render_pv`。

| 指标 | 公式 | 含义 | 看板 |
| --- | --- | --- | --- |
| 款式曝光 UV | 去重看到该款式的 user_id | 分母，判断样本量 | 总览/款式 |
| 款式曝光 PV | 该款式被展示次数 | 推荐位覆盖能力 | 款式 |
| 试戴率 | 试戴人数 / 曝光人数 | 是否愿意上手体验 | 总览/款式 |
| 我想做率 | 我想做人数 / 曝光人数 | 是否愿意加入候选 | 总览/款式 |
| 直接确认率 | card/detail 确认人数 / 曝光人数 | 第一眼或详情页成交力 | 总览/款式 |
| 试戴后确认率 | tryon_result 确认人数 / 试戴结果查看人数 | AI 试戴转化能力 | 核心 |
| 试戴后想要率 | tryon_result 我想做人数 / 试戴结果查看人数 | 试戴后进入候选池比例 | 核心 |
| 想要转确认率 | want_list 确认人数 / 我想做人数 | 候选池转预约能力 | 核心 |
| 总确认率 | 所有来源确认人数 / 曝光人数 | 综合商业转化 | 核心 |

## 6. 确认来源拆分

`confirm_source` 必须记录来源：

| 来源 | 含义 | 业务价值 |
| --- | --- | --- |
| `card` | 款式卡片直接确认 | 第一眼强吸引 |
| `detail` | 详情页确认 | 信息充分后强意向 |
| `tryon_result` | 试戴结果页确认 | AI 上手效果促成转化 |
| `want_list` | 我想做列表确认 | 候选沉淀后转化 |

`intent_source` 也要记录：

| 来源 | 含义 |
| --- | --- |
| `card` | 款式卡片加入我想做 |
| `detail` | 详情页加入我想做 |
| `tryon_result` | 试戴结果页加入我想做 |

## 7. 热门趋势定义

不建议只用“试戴次数最多”定义热门。更合理的是多路径行为强度：

```text
BehaviorHeat =
1 * BrowseUV
+ 2 * TryOnUV
+ 3 * WantUV
+ 4 * TryOnWantUV
+ 5 * DirectConfirmUV
+ 6 * TryOnConfirmUV
```

归一化：

```text
NormalizedHeat = BehaviorHeat / BrowseUV
```

运营版热门趋势：

```text
热门趋势款 =
曝光样本充足
+ 总确认率高
+ 试戴后确认率高
+ 近 7 天确认增长高
```

推荐系统版：

```text
HotTrendScore =
0.20 * WantRate 分位数
+ 0.20 * TryOnRate 分位数
+ 0.25 * TryOnConfirmRate 分位数
+ 0.20 * DirectConfirmRate 分位数
+ 0.15 * WantToConfirmRate 分位数
```

如需加趋势增长：

```text
HotTrendScore =
0.15 * WantRate 分位数
+ 0.15 * TryOnRate 分位数
+ 0.25 * TryOnConfirmRate 分位数
+ 0.20 * DirectConfirmRate 分位数
+ 0.15 * WantToConfirmRate 分位数
+ 0.10 * 近 7 天增长分
```

## 8. 款式分层

| 分层 | 判断 | 运营动作 |
| --- | --- | --- |
| 爆款 | 高试戴 + 高确认 / 高试戴后确认 | 首页推荐、主推 |
| 引流款 | 高试戴 + 低确认 | 保留曝光，但优化详情/价格/适配说明 |
| 潜力款 | 低试戴 + 高确认 | 增加曝光，换封面测试 |
| 弱势款 | 低试戴 + 低确认 | 降权、替换、复盘 |
| 第一眼成交款 | 直接确认率高 | 适合卡片页主推 |
| 试戴转化款 | 试戴后确认率高 | 适合 AI 推荐和一键试戴 |
| 候选沉淀款 | 我想做高，确认慢 | 适合优惠/档期提醒 |

## 9. 冷门预警定义

冷门不能只看低热度，必须先判断样本量。

```text
如果曝光 < B_min，则标记为“样本不足”，不判断冷门。
```

建议 MVP 阈值：

```text
B_min = 100 次曝光 或 30 个曝光用户
```

冷门类型：

| 类型 | 判断 | 可能原因 |
| --- | --- | --- |
| 样本不足 | 曝光低 | 推荐位不够，不能判断 |
| 第一眼冷门 | 曝光足够，但试戴率、我想做率、直接确认率都低 | 封面、款式、标签、人群不匹配 |
| 试戴后冷门 | 试戴率高，但试戴后确认率低、试戴后想要率低 | 上手效果劝退 |
| 候选沉淀冷门 | 我想做率高，但想要转确认率低 | 价格、档期、门店可做性、犹豫 |
| 详情劝退 | 卡片点击高，但详情页确认低 | 价格/时长/风险说明劝退 |
| 门店履约冷门 | 确认要做高，但到店后换款高 | 线上效果和线下服务不一致 |

